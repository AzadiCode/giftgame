# XZ GIFT — مینی‌اپ بازی تلگرام

یک پروژه‌ی شروع مستقل با ظاهر فارسی و راست‌چین، بک‌اند Flask، دیتابیس MongoDB و رابط کاربری تک‌صفحه‌ای.

## امکانات موجود
- احراز هویت Telegram Mini App با اعتبارسنجی HMAC روی سرور
- ایجاد پروفایل و موجودی اولیه‌ی سکه‌های **مجازی**
- گردونه روزانه با محدودیت یک‌بار در روز
- بازی‌های آزمایشی Crash و Mines با نتیجه‌ای که سمت سرور تعیین می‌شود
- رتبه‌بندی کاربران
- تاریخچه تراکنش‌ها
- endpoint مدیریتی برای اصلاح موجودی با شناسه مدیر
- رابط واکنش‌گرا با حالت تاریک، کارت‌های بازی و پنجره‌های تعاملی

## هشدار مهم
این پروژه نسخه‌ی پایه/آزمایشی است. **واریز، برداشت، اتصال کیف پول، پرداخت واقعی یا شرط‌بندی با دارایی واقعی پیاده‌سازی نشده‌اند.** همه‌ی امتیازها و سکه‌ها در این نسخه مجازی‌اند. برای محصول واقعی باید بررسی امنیتی مستقل، آزمون بار، پایش، پشتیبان‌گیری، کنترل تقلب، سیاست‌های حقوقی/منطقه‌ای و طراحی دفترکل تراکنش‌ها انجام شود. بازی‌ها در این نسخه نمونه‌ی ساده هستند و نباید به‌عنوان بازی مالی واقعی عرضه شوند.

## پیش‌نیازها
- Python 3.10+
- MongoDB برای نگهداری دائمی داده‌ها (در نبود `MONGO_URI` از دیتابیس موقت در حافظه استفاده می‌شود)
- ربات تلگرام ساخته‌شده با BotFather
- HTTPS عمومی برای اجرای Mini App در تلگرام

## اجرای محلی
```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
source .venv/bin/activate
pip install -r requirements.txt
```
متغیرهای محیطی را در ترمینال تنظیم کن؛ Flask به‌صورت خودکار فایل تنظیمات نمی‌خواند. سپس:
```bash
# Linux/macOS
export BOT_TOKEN=""
export BASE_URL="http://localhost:10000"
python app.py
```
در ویندوز PowerShell به‌جای `export` از `$env:BOT_TOKEN=""` و `$env:BASE_URL="http://localhost:10000"` استفاده کن.
وقتی `BOT_TOKEN` خالی باشد، حالت توسعه با کاربر آزمایشی فعال است. **این حالت فقط برای تست محلی است**؛ قبل از استقرار حتماً `BOT_TOKEN` و `MONGO_URI` واقعی را تنظیم کن. با `BOT_TOKEN` تنظیم‌شده، درخواست‌ها بدون `X-Telegram-Init-Data` معتبر رد می‌شوند.

## استقرار در Render از طریق داشبورد (بدون فایل‌های تنظیمات اضافی)
این پروژه برای استقرار به فایل `render.yaml` یا `.env.example` نیاز ندارد. در GitHub کافی است فایل‌های اصلی پروژه را آپلود کنی. سپس در داشبورد Render سرویس Web Service بساز و این تنظیمات را وارد کن:

- **Runtime:** Python 3
- **Build Command:** `pip install -r requirements.txt`
- **Start Command:** `gunicorn app:app --workers 2 --threads 4 --timeout 90`

در بخش **Environment Variables** این متغیرها را اضافه کن:

| نام | مقدار |
|---|---|
| `BOT_TOKEN` | توکن واقعی ربات از BotFather |
| `BASE_URL` | آدرس عمومی سرویس Render با `https://` و بدون `/` انتهایی |
| `MONGO_URI` | آدرس اتصال MongoDB دائمی |
| `MONGO_DB` | `xzgift` |
| `ADMIN_IDS` | شناسه عددی تلگرام مدیر؛ چند شناسه را با کاما جدا کن |
| `STARTING_BALANCE` | `1000` |
| `DAILY_SPIN_REWARD_MIN` | `10` |
| `DAILY_SPIN_REWARD_MAX` | `150` |
| `INIT_DATA_MAX_AGE` | `86400` |
| `PORT` | معمولاً لازم نیست دستی تنظیم شود؛ Render آن را فراهم می‌کند |
| `LOG_LEVEL` | `INFO` |
| `TELEGRAM_WEBHOOK_SECRET` | اختیاری؛ می‌توانی خالی بگذاری تا از `BOT_TOKEN` ساخته شود |

مقادیر نمونه را عیناً برای توکن و دیتابیس استفاده نکن. پس از ذخیره متغیرها، Deploy/Restart کن. هنگام شروع سرویس، وب‌هوک تلگرام روی مسیر `/telegram/webhook` ثبت می‌شود و دکمه‌ی منوی مینی‌اپ تنظیم می‌شود؛ فرمان `/start` باید پیام خوش‌آمد و دکمه‌ی «باز کردن XZ GIFT» را بفرستد.

برای بررسی، آدرس `https://YOUR_DOMAIN/health` را باز کن؛ باید پاسخی با وضعیت `ok` دریافت کنی. در لاگ سرویس نیز عبارت `Telegram webhook configured` را بررسی کن.

## APIها
- `GET /api/me` — پروفایل و ۸ تراکنش اخیر
- `GET /api/leaderboard` — رتبه‌بندی
- `POST /api/spin` — گردونه روزانه
- `POST /api/game/crash` — بدنه: `{"bet":10,"cashout":1.5}`
- `POST /api/game/mines` — بدنه: `{"bet":10,"picks":2}`
- `POST /api/admin/credit` — فقط مدیر؛ بدنه: `{"telegram_id":123,"amount":100}`

درخواست‌های API در تولید باید از Telegram Mini App و با هدر `X-Telegram-Init-Data` معتبر بیایند.

## ملاحظات تولید
- این نسخه نمونه‌ی شروع است، نه «بی‌نقص/تضمین‌شده»؛ باید در محیط مقصد تست شود.
- برای عرضه عمومی، انتقالات مالی را با دفترکل immutable/دوطرفه، idempotency key، تراکنش‌های دیتابیس و کنترل رقابت پیاده‌سازی کن.
- rate limiting، محافظت در برابر abuse، CSP، سیاست حریم خصوصی، لاگ ساختاریافته، هشدار خطا، پشتیبان‌گیری و آزمون خودکار اضافه شود.
- اگر MongoDB standalone است، قابلیت تراکنش چندسندی ممکن است در دسترس نباشد؛ برای عملیات مالی واقعی Replica Set و طراحی صحیح لازم است.
- در نسخه فعلی، سهمیه‌ی گردونه با unique index کنترل می‌شود؛ تاریخ روز بر اساس timezone سرور است.
